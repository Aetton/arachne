# Как помочь проекту

Arachne — компактный портал для запуска CI/CD-сценариев, инфраструктурной
автоматизации, просмотра логов и получения ссылок на артефакты.

## Основные правила

- Оставляйте ядро универсальным. Логику конкретного продукта или компании держите
  в локальных сценариях.
- Не коммитьте секреты, токены, приватные ключи, внутренние адреса, production-логи,
  данные клиентов и локальные сертификаты.
- В примерах используйте адреса вида `*.example.internal`, имена `example-*` и
  локальные demo-сервисы.
- Новые исполнители подключайте через интерфейс пауков. Так зависимости от
  конкретного backend останутся за границами ядра.
- Сценарии должны оставаться понятными оператору без чтения исходников.

## Локальная разработка

```bash
cp .env.example .env
make up
make logs
```

Чтобы пересобрать проект после изменений:

```bash
make update
```

Документация находится в `docs/`. Перед отправкой изменений проверьте её так:

```bash
cd docs
npm ci
npm run docs:build
```

## Pull request

Хороший PR коротко отвечает на пять вопросов:

- что изменилось;
- зачем это понадобилось;
- что заметит оператор;
- есть ли нюансы совместимости;
- как вы проверили результат.
