# Политика безопасности

## Как сообщить об уязвимости

Не публикуйте уязвимости в открытых GitHub Issues. Используйте приватный канал,
указанный для репозитория, или свяжитесь с сопровождающими напрямую.

В сообщении укажите:

- версию или commit;
- способ развёртывания;
- возможные последствия;
- шаги воспроизведения;
- нужные для разбора логи, предварительно удалив из них секреты.

## Чувствительные данные

Не добавляйте в issues, pull requests, скриншоты и примеры секреты, приватные
ключи, токены, внутренние адреса, данные клиентов и production-логи.

Используйте безопасные заглушки:

```text
forgejo.example.internal
nexus.example.internal
arachne.example.internal
```

## Поддерживаемые версии

Arachne пока не достигла версии 1.0. По умолчанию исправления безопасности
попадают в ветку `main`; отдельная release-ветка поддерживается только после
явного объявления.
