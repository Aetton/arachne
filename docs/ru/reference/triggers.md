# Триггеры

Триггеры считываются и связываются при старте приложения. Публикация новой версии
сценария не обновит активные cron и подписки до рестарта.

## `manual`

```yaml
triggers: [{type: manual}]
```

Фоновой логики нет: форму запуска вызывает пользователь после проверки ACL.

## `schedule`

```yaml
triggers:
  - type: schedule
    cron: "0 2 * * *"
    params:
      branch: main
      version: nightly
```

Используется пятичастный cron APScheduler. Параметры передаются ровно из
`trigger.params`; defaults браузерной формы не достраиваются.

ID job — `sched:<scenario-slug>`. Несколько schedule у одного сценария заменяют
друг друга, поэтому фактически останется последний.

## `chain`

```yaml
triggers:
  - type: chain
    after: build-nightly
    on: success
```

Запускает новый независимый run, когда сценарий из `after` завершился статусом `on`.
По умолчанию ждётся `success`. Параметры дочернего запуска пусты, результат не меняет
уже завершившегося предка.

Для упорядоченного дочернего запуска с передачей логов используйте паука `scenario`.

## Грабли

- schedule без `cron` и chain без `after` молча не связываются;
- неизвестный тип печатается в лог приложения и пропускается;
- автоматические запуски не проходят пользовательский ACL;
- таймзона scheduler отдельно не задаётся;
- циклы chain не обнаруживаются;
- `source` запуска принимается движком, но в таблице runs не сохраняется.
