# Сценарии

Сценарий — это форма запуска, триггеры и последовательность шагов. В интерфейсе пользователь видит красивое название, а внутри всё держится на стабильном slug.

## Где источник истины

Опубликованные сценарии хранятся в PostgreSQL. Файл `config/scenarios.yaml` добавляет slug при первом импорте. После этого сценарием управляет база, и правки seed-файла на него уже не влияют.

Если `SCENARIOS_CONFIG` не найден, загрузчик последовательно попробует:

1. путь из переменной;
2. `config/scenarios.yaml`;
3. `config/scenarios.yaml.example`.

## Версии

При редактировании сценария создаётся новая версия. У существующих запусков сохраняются ID версии и неизменяемый снимок описания, поэтому последующие изменения не переписывают историю выполнения.

Административная форма сразу публикует новую версию и переводит предыдущую в `archived`. При восстановлении Arachne копирует выбранную старую версию в новую и публикует копию.

Статусы версий в модели:

- `draft` — создана, но ещё не опубликована;
- `published` — используется для новых запусков;
- `archived` — была опубликована раньше.

## Slug

Slug участвует в URL, ACL, истории и цепочках. Допустимы строчные латинские буквы, цифры, `.`, `_` и `-`; первый символ — буква или цифра; длина — до 64 символов.

Администратор может переименовать slug. При этом поле `scenario` в старых запусках обновится. Ссылки на slug в других сценариях и триггерах автоматически не переписываются — их нужно поправить руками.

## Inputs и параметры инфраструктуры

Параметры формы можно напрямую передавать во вложенный `with`. Подстановки разрешаются рекурсивно, поэтому resource-настройки не требуют специальных костылей.

Пример формы временного стенда:

```yaml
params:
  - name: os
    label: ОС
    type: choice
    default: redos8
    options: [redos7, redos8, windows]

  - name: lifetime
    label: Сколько жить
    type: choice
    default: 30m
    options: [30m, 1h, 2h, 4h, 8h, 1d]

  - name: memory_gb
    label: RAM, GiB
    type: string
    default: ""

steps:
  - id: vm
    spider: tofu-proxmox
    action: provision
    with:
      name: "${params.name}"
      os: "${params.os}"
      lifetime: "${params.lifetime}"
      resources:
        memory_gb: "${params.memory_gb}"
```

`RunContext` разрешает ссылки рекурсивно внутри mappings и lists. Если значение состоит только из `${params.X}`, сохраняется исходный тип параметра/результата, когда он уже типизирован.

Сейчас UI params в основном представлены `string`, `boolean`, `choice` и `select`, поэтому числовые поля формы могут приходить строками. `tofu-proxmox` валидирует `cpu`, `memory_gb` и `disk_gb` как положительные целые числа.

## Golden Image как input

Обычный сценарий может вообще не показывать выбор образа:

```yaml
with:
  os: redos8
```

Тогда используется Golden Image profile `redos8`.

Если нужно дать выбор нескольких образов одного семейства:

```yaml
with:
  os: redos8
  image: "${params.image}"
```

Enabled Golden Image profiles также публикуются в editor metadata, чтобы редактор мог предлагать актуальные profile keys.

Сценарию не нужны VM ID, node, datastore, system disk interface и другие Proxmox/OpenTofu internals.

## Lifetime

`lifetime` является пользовательским свойством машины, а не scheduler syntax:

```yaml
with:
  lifetime: 30m
```

Поддерживаются минуты, часы и дни в компактной форме (`m`, `h`, `d`). Spider валидирует значение и передаёт его в lifecycle registry. После создания VM Arachne вычисляет `expires_at` в PostgreSQL.

Если `lifetime` не указан, VM не получает автоматический TTL.

## Resource overrides

Можно запросить все ресурсы:

```yaml
resources:
  cpu: 8
  memory_gb: 16
  disk_gb: 80
```

или один:

```yaml
resources:
  memory_gb: 16
```

Незапрошенные ресурсы наследуются от Golden Image. Disk разрешено только увеличивать относительно фактического system disk выбранного Proxmox template.

## Импорт и экспорт

**Export YAML** выгружает опубликованные сценарии, компоненты и разрешающие ACL.
Импорт выполняется браузером через те же административные формы:

- **Add only** создаёт отсутствующие элементы и пропускает существующие;
- **Update existing** обновляет компоненты и создаёт новую опубликованную версию существующего сценария.

Golden Image profiles не являются частью scenario YAML export. Это отдельная управляемая сущность Arachne и переносится вместе с PostgreSQL.

Импорт проверяет структуру до отправки. Смешанные `match: all` и `match: any` для разных действий одного сценария редактор сохранить не может.

## Доступ

Чтобы увидеть или запустить сценарий, мало состоять в подходящей роли. Сначала проверяется возможность роли, затем ACL конкретного сценария. Администратор обходит обе проверки. Полная схема — на странице [Роли и доступ](/ru/user-guide/access).
