# Работа оператора

Операторский интерфейс состоит из списка сценариев, списка запусков и рабочей области. Детали backend-а должны оставаться под полом: пользователь работает с понятными входами и результатами, а не с параметрами OpenTofu или Proxmox.

## Вход

Откройте портал и войдите локальной учётной записью. Сессия хранится в cookie `arachne_session`: она недоступна JavaScript, действует семь дней по умолчанию и проверяется при каждом защищённом запросе.

Если учётная запись выключена администратором, уже выданная сессия перестанет работать при следующем запросе.

## Поиск и выбор сценария

Сценарии слева сгруппированы по компонентам. Поиск смотрит на slug и название сценария, а также slug и название компонента. Состояние раскрытых групп сохраняется в браузере.

Если сценария не видно, причина почти всегда одна из трёх:

- он выключен или не имеет опубликованной версии;
- у вашей роли нет `scenarios.view`;
- ACL сценария не разрешает вам просмотр.

## Форма запуска

Нажмите на сценарий. Arachne построит форму из `params` опубликованной версии.

| Тип | Как выглядит | Что уходит в запуск |
|---|---|---|
| `string` | текстовое поле | строка |
| `boolean` | флаг | `true` или `false` |
| `choice` | обычный список | выбранная строка |
| `select` | список; для веток — поиск | выбранная строка |
| неизвестный тип | текстовое поле | строка |

Динамический список веток загружается из Forgejo при открытии формы. Если API недоступен, поле блокируется и под ним показывается настоящая ошибка.

## Временные стенды

Сценарий может давать пользователю простые параметры машины, например:

```text
ОС
образ
сколько жить
CPU
RAM
диск
```

На уровне scenario это превращается в `os`, optional `image`, `lifetime` и `resources`. Пользователь не должен указывать VM ID, node, datastore, disk interface или OpenTofu variables.

Пример пользовательского намерения:

```yaml
with:
  name: quick-test
  os: redos8
  lifetime: 30m
  resources:
    memory_gb: 16
```

Если `image` не указан, Arachne использует Golden Image profile с ключом, равным `os`. Если администратор завёл несколько образов одного семейства, сценарий может дать пользователю выбор между ними.

## Срок жизни машины

`lifetime` задаётся компактно:

```text
30m
2h
1d
```

Если срок указан, после provision Arachne сохраняет абсолютный `expires_at` в PostgreSQL. Машина будет автоматически удалена lifecycle reaper-ом после истечения срока.

Рестарт Arachne не начинает отсчёт заново.

Если `lifetime` отсутствует, автоматическое удаление не назначается и нужен explicit destroy или другой cleanup сценария.

## Запуск и живые логи

После нажатия **Spin thread** создаётся UUID запуска и открывается его карточка. Логи приходят через Server-Sent Events примерно каждые `0,4` секунды.

В карточке есть:

- параметры запуска;
- общий статус: `running`, `success`, `failed` или `cancelled`;
- шаги и паук каждого шага;
- группы Ansible `PLAY`, `TASK`, `RUNNING HANDLER`, `PLAY RECAP`;
- поиск по логу, перенос строк, автопрокрутка и копирование;
- артефакты шага и общий список ссылок после успешного запуска.

Строка из `stderr`, `fatal:`, `failed:`, `ARACHNE ERROR`, `PORTAL ERROR` или структурная ошибка помечают группу как упавшую.

## VM artifact

Временная машина возвращается как структурированный `vm` artifact. В нём могут быть:

```text
name
vm_id
ip
os
connection type
port
requested_resources
lifetime
state
```

Backend metadata сохраняются для lifecycle, но обычному пользователю не требуется думать о source node, template VM ID или datastore.

Если VM уже создана, но QEMU Guest Agent ещё не вернул IP, run может завершиться ошибкой получения адреса. При этом Arachne всё равно регистрирует VM для cleanup, если известен `vm_id`.

## История

Список запусков обновляется каждые три секунды и показывает не больше 15 последних записей. Обычный пользователь видит свои запуски, администратор — общие.

Завершённый запуск читается из базы. Он сохраняет параметры, статус, время, структурированные логи, structured artifacts, ID версии и снимок определения сценария.

## Отмена

Кнопка **Cancel run** отправляет сигнал отмены всем шагам сценария. Реально отменится только активный шаг, если его паук умеет резать свою нить:

- `forgejo` вызывает endpoint отмены Actions run;
- `ansible-local` посылает процессу `SIGTERM`;
- остальные встроенные пауки пока не реализуют полноценную отмену.

Отмена работает в режиме best-effort. Успешный ответ подтверждает отправку сигнала; внешний исполнитель в этот момент ещё может работать.

## Артефакты и управляемые ресурсы

Для обычных package/artifact Arachne хранит metadata и ссылку, а файл остаётся в Forgejo, Nexus или другом хранилище.

VM отличается: это не просто ссылка на скачивание, а управляемый ресурс. Arachne хранит lifecycle state в `managed_machines`, чтобы машину можно было удалить вручную или автоматически по TTL.

Пользовательский UI управления VM будет развиваться отдельно: credentials и встроенная console являются следующими слоями над уже существующим lifecycle.
