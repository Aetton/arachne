# Администрирование

Административные страницы открываются только для роли `admin`. Возможности вроде
`users.manage` уже есть в модели, но HTTP-маршруты пока их не проверяют.

## Пользователи

В **Admin → Users** можно создать пользователя, изменить его имя, пароль, роли,
команды и состояние, а также удалить его.

Особенности:

- логин уникален и после создания в форме не меняется;
- новый пароль обязателен;
- если API создания получит пустой пароль в обход браузерной проверки, будет
  использован `changeme`;
- при редактировании пустое поле пароля оставляет старый хеш;
- выключенный пользователь не может войти и не проходит проверку существующей сессии;
- удалить самого себя через интерфейс нельзя;
- удаление пользователя не удаляет историю его запусков каскадом.

Аутентификация сейчас только локальная. Поле `auth_source` уже есть в модели, но LDAP
ещё не подключён.

## Роли

Роль собирает возможности и может наследовать другие роли. Наследование обходится
рекурсивно, а повторно встреченная роль пропускается. Цикл запрос не повесит, но и
полезного смысла у такого наследования нет.

Системные роли создаются при старте:

| Роль | Возможности |
|---|---|
| `admin` | все системные возможности и обход ACL |
| `developer` | просмотр и запуск сценариев |
| `tester` | просмотр и запуск сценариев |

Форма сохраняет роль по slug: повторная отправка существующего slug обновит имя,
описание, наследование и полный набор возможностей.

## Команды

Команда задаёт продуктовую область и используется как вторая ось ACL. Пользователь
хранит ID команд, а ACL может ссылаться как на числовой ID, так и на slug — проверка
понимает оба варианта.

При старте создаются команды `frontend`, `backend` и `protocol`, если их ещё нет.
Поле компонентов вводится через запятую. Вспомогательный фильтр конфигурации
понимает `*`. Основной dashboard сейчас проверяет ACL.

## Сценарии и компоненты

На странице сценариев можно:

- создать или изменить компонент;
- удалить неиспользуемый компонент;
- создать сценарий;
- открыть YAML-редактор существующего сценария;
- изменить slug сценария;
- назначить ACL;
- просмотреть версии и восстановить старую;
- импортировать или экспортировать YAML.

Серверная проверка при сохранении требует `label`, `component`, непустой `steps`,
a у каждого шага — `id`, `spider`, `action` и уникальный ID. Браузерный редактор
проверяет больше полей для ранней подсветки ошибок; сервер всё равно валидирует
запрос отдельно.

## Первоначальный администратор

Пользователь `admin` создаётся только при отсутствии такого логина. Его пароль берётся
из `ADMIN_PASSWORD`, а при отсутствии переменной — из небезопасного значения `admin`.
После появления записи изменение переменной пароль не обновляет.
