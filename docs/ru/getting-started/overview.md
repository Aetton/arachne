# Обзор

Arachne работает как общий пульт для Forgejo, Ansible, OpenTofu и временной инфраструктуры. Она хранит сценарии, строит форму запуска, вызывает шаги по порядку и собирает результат.

Обычный запуск выглядит так:

1. пользователь выбирает доступный ему сценарий;
2. Arachne собирает параметры формы и создаёт запись запуска;
3. оркестратор идёт по шагам сверху вниз;
4. каждый шаг передаётся своему пауку;
5. логи летят в интерфейс, а structured artifacts попадают в контекст следующих шагов;
6. первый провал или отмена останавливает оставшиеся шаги;
7. итог, логи, параметры и артефакты сохраняются в базе.

## Основные понятия

- **Сценарий** — опубликованное и версионируемое описание формы, триггеров и шагов.
- **Компонент** — группа сценариев в интерфейсе: название секции, иконка и порядок.
- **Шаг** — одна операция одного паука. Шаги пока выполняются строго последовательно.
- **Паук** — адаптер к исполнителю: Forgejo Actions, локальному Ansible, OpenTofu или другому сценарию Arachne.
- **Нить** — выполнение одного шага через шину.
- **Триггер** — способ начать сценарий: вручную, по cron или после другого сценария.
- **Артефакт** — унифицированный результат шага: пакет, архив, Actions artifact, виртуальная машина или другой объект с metadata.
- **Golden Image** — человеческий профиль, который связывает сценарий с конкретным Proxmox template. Профиль хранит выбор template, но не дублирует его node/storage/CPU/RAM/disk.
- **Managed machine** — VM, жизненным циклом которой владеет Arachne. Для неё сохраняются ID, IP, состояние, TTL и backend metadata для cleanup.
- **Запуск** — конкретное выполнение сценария. Оно хранит снимок версии, поэтому последующее редактирование сценария историю не переписывает.
- **Шина** — транспорт между оркестратором и исполнителями. В одном процессе это память, для разнесённой схемы предусмотрен NATS.

## Принцип инфраструктурного слоя

Сценарий описывает намерение:

```yaml
with:
  name: test-001
  os: redos8
  lifetime: 30m
  resources:
    memory_gb: 16
```

Пользователь не указывает VM ID, Proxmox node, datastore, disk interface или OpenTofu variables.

Arachne сама проходит цепочку:

```text
scenario
  -> Golden Image profile
  -> Proxmox API discovery
  -> OpenTofu
  -> VM artifact
  -> managed_machines
```

Если машине задан `lifetime`, Arachne хранит абсолютный `expires_at` в PostgreSQL и удаляет VM после истечения срока.

## Golden Images

Golden Images настраиваются администратором в **Control -> Golden Images**.

Для обычного `os: redos8` используется профиль с ключом `redos8`. Если образов несколько, сценарий может выбрать конкретный:

```yaml
with:
  os: redos8
  image: redos8-clean
```

Фактические node, CPU, RAM, disk и storage Arachne читает live из Proxmox API. Они не хранятся вторым набором переменных в `.env`.
