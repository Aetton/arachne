# Проверка и рефакторинг приложения — 22 октября 2026

## Исправленные дефекты

- ACL с `match=any` больше не трактует отсутствующее измерение (роль/команду)
  как разрешение. Набор из одних deny-правил ничего не разрешает.
- Сохранение сценария, публикация версии и замена ACL теперь выполняются одной
  транзакцией. Ошибка замены ACL откатывает и определение, и публикацию.
- Редактор сценария без опубликованной версии загружает последний черновик.
- Запросы изменения структуры проверяются Pydantic: неправильные типы и
  повреждённый JSON возвращают 422 вместо необработанного исключения.
- Определение проверяет строковые поля и идентификаторы шагов, а `sort_order`
  проверяется как 32-битное целое до изменения БД.
- Поиск на дашборде временно раскрывает группы, не теряя сохранённое пользователем
  состояние после очистки поиска.

## Рефакторинг

- Операции изменения структуры вынесены из HTTP-маршрута в `scenario_layout.py`.
- Дашборд читает сценарии и опубликованные версии одним JOIN вместо отдельных
  запросов для каждой группы и версии. ACL проверяется отдельно для каждого сценария.
- Менеджер сценариев индексирует строки по группам вместо повторного полного
  перебора соседей каждой строки. Ошибки валидации отображаются текстом.
- Затронутые Python-модули приведены к Ruff-format, JS/CSS менеджера — к Prettier.
- Добавлен единый runner `scripts/check.py` и фиксированные зависимости инструментов.

## Проверки и ограничения

В изолированных процессах прошли 53 Python-теста и 8 Node/DOM-тестов.
Проверены синтаксис всех standalone JS-файлов и неопределённые имена во всём `api`.
DOM-тесты проверяют поведение, но не заменяют визуальную проверку в браузере.
Среда запрещает запуск Chromium через socket(), поэтому визуальный прогон
не выполнен. Реальные API гипервизоров и PostgreSQL в этом прогоне не использовались.
Миграции БД этот PR не добавляет.

Этот проход не означает, что в приложении больше нет дефектов. Крупные отдельные
направления следующего рефакторинга: атомарный пакетный YAML-импорт (сейчас операции
выполняются последовательно), разделение остальных admin-маршрутов и управление
общими frontend-компонентами без копирования обработчиков между страницами.
